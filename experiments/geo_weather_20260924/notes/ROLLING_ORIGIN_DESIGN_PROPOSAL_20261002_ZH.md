# 多起报点数据设计：提案（2026-10-02，待 PI 决定；未采用）

## 为什么要改
- 现在每个事件只有一个起报点，在风暴之前。这个设定下，误差由"哪个县会被打中"决定，公开输入给不出这部分信息（信息上限探针）；恢复侧的结构被盖住。
- 今晚的检验表明，风暴开始之后，恢复侧有可学的结构：自身规模饱和，加上邻县的停电状态（[结果](RESTORATION_CAPACITY_PROBE_RESULTS_20261002_ZH.md)）。这些只有在起报点位于风暴开始之后才能评估。
- 同一个模型可以覆盖两种起报：风暴之前，存量和区域负担都接近 0，恢复核不起作用，模型退回宿主；风暴之后，恢复核起作用。所以这是扩展，不是放弃原任务。

## 提案

| 项目 | 建议 | 备选 |
|---|---|---|
| 县-事件、事件折、设计权重 | 不变（8,457 个县-事件，81 个系统） | — |
| 起报点 | 登记起报点之后 0、48、96 小时（3 个） | 0、24、48、72、96 小时（5 个，训练成本约 5 倍） |
| 预测时长 | 每个起报点预测 48 小时（各起报点可比）；起报点 0 另保留登记的 144 小时指标 | 预测到窗口结束 |
| 起报时可用的输入 | 起报前 72 小时的自身停电；起报前一小时三个距离环的邻县停电比例（完整 EAGLE-I）；预测时段的天气（ERA5，等同完美预报） | 加 HRRR |
| 训练 | 一个模型在全部起报点上联合训练，每个样本的权重 = 设计权重 ÷ 起报点个数 | 每个起报点单独训练 |
| 主指标 | 各起报点合并的 48 小时设计加权 RMSE | — |
| 分层指标 | 起报时尚未停电 / 已在停电；S 单元；各天气类型；起报点 0 的登记指标（不得变差） | 按阶段再分"上升中 / 已过峰值" |
| 区间 | 类别内 family cluster bootstrap（同一县-事件的多个起报点在同一个簇里） | — |
| sealed C | 同样的起报点规则；设计冻结前不触碰 | — |

## 必须带的基线和对照
- **基线**：在同一批样本上重新训练的宿主；持续性（存量不变）；同样输入的 LightGBM（这个任务的信息上限）。可选：TimesFM 一类的时间序列基础模型，用起报前的历史零样本预测。
- **核的对照**（文献核查指出审稿人会要求的）：
  - 只有自身规模饱和（基线）；
  - 区域负担在县-事件间打乱、在同一场风暴内打乱（两个 null）；
  - 区域负担只作为恢复网络的普通输入（不经过核）；
  - 区域负担放在损伤侧（已发表的加性激发形式）。

## 今晚已有的依据和它的限度
- 事后模拟（宿主速率不变，只改恢复项，四个起报点）：自身规模饱和 + 区域项相对宿主 +8.3% [+4.3, +11.8]，已在停电的样本 +21.9%。
- 收益全部在已经停电的县上（占宿主误差的 43%）；尚未停电的县（57%）没有任何写法能帮上。
- 区域项在自身规模饱和之外的增量约 3 个百分点；对风暴内打乱的 null，区间含 0（+2.1% [−0.2, +4.9]）。
- 训练对比目前只有一个起报点（后移 48 小时）的单 seed 初筛。

## 需要 PI 决定的
1. 是否把多起报点评估作为主设计。
2. 起报点取 3 个还是 5 个；预测时长取 48 小时还是到窗口结束。
3. 论文的主张是否从"地理调制损伤"转到"状态与空间耦合的恢复"。
4. 是否值得为这个任务加 HRRR 和基础模型基线。
