# 夜间结果（2026-10-02，PI 离开期间；Claude Code）

三件事都做了：文献核查、数据分析、单 seed 实验。只用公开数据 D；没有读 sealed C；没有改 `paper_v1/`。

## 结论

1. **剂量—易损性核不过关。** 主候选 DKV 相对宿主：严重县-事件（S，窗口内观测峰值 ≥10%）+1.39% [+0.03, +3.00]，但严重假峰 38 个（规则是不超过 20），全体 −0.27%。按登记规则不是候选。去掉易损性向量的 DK 略好（S +1.62% [+0.41, +3.12]，全体 +0.21%），假峰仍有 34 个。易损性向量（地理先验 + 历史）没有贡献。
2. **静态地理今晚又有三次检验，都没有过关**：事件级的地理先验、恢复侧（慢恢复域）、以区域负担为条件的恢复侧。至此地理描述量在约十个检验里都没有事件级证据。
3. **找到了第一个过关的空间信号：一个县恢复得快还是慢，取决于它周围的县是不是也在停电。** 这是"空间邻近"意义上的地理，不是地形、冠层这类描述量。
   - 邻县安静时，本县停电再大，24 小时内也基本恢复；邻县也在停电时，小停电也恢复得慢。
   - 加入 150 km 内邻县的停电比例后，峰后 24 小时剩余比例的折外 R² 从 0.08 升到 0.53（只用峰值时刻的邻县停电时为 0.39）。天气类型标签此后没有增量。
   - 作用随距离衰减，50 km 最强；不以州界为限。
   - 图：`figures/restoration_by_neighbour_burden.png`（峰后恢复曲线，按邻县停电状态分组）。
4. **这个信号只能在风暴开始之后用。** 风暴之前，区域负担无法由 ERA5 预测。把起报点移到风暴开始之后（滚动起报），事后模拟的收益是：全体 +8.3% [+4.3, +11.8]，起报时已在停电的县 +21.9% [+14.7, +30.9]，热带 +26.4%。其中自身规模饱和约占 5 个百分点，区域负担约占 3 个百分点。
   - 收益全部在起报时已经停电的县上（占宿主误差的 43%）。尚未停电的县（57%）没有任何写法能帮上，上风向邻县的停电也不能预示谁下一个被打中。
5. **之前推不动的原因更清楚了。** 在风暴前起报的设定里，误差由"哪个县会被打中"决定，这部分公开输入给不出信息。恢复侧有可学的结构，但被这层不确定性盖住：今晚的剂量核学到了正确的恢复放慢，在原设定下没有收益，放到滚动起报下相对宿主 +4.0% [+0.7, +7.4]。
6. **据此实现了"恢复核"，训练对比过关（单 seed，事件五折，留出事件）。** 起报点后移 48 小时，宿主在同一面板上重新训练作基线。
   - 全体 +7.8% [+2.4, +17.7]；起报时已在停电的县 +23.9% [+8.6, +46.7]；五折全部为正；没有哪个天气类型变差（热带 +25.1%）。
   - 模型自己把放慢集中到了热带（已停电县的恢复放慢 5.9 倍，其他类型 1.2–1.9 倍），没有用天气类型标签。训练里起作用的是空间项，自身规模饱和的权重接近 0。
   - 只在这一个起报点训练的核，直接用到后移 24、72、96 小时的起报点，全体 +7.3%、+8.2%、+21.4%，区间都不含 0；用到登记的风暴前起报点，原任务不变（144 小时全体 +0.8% [−0.2, +2.1]）。
   - 图：`figures/roll_trajectories_48.png`。
   - 对照 arm（只有自身状态、打乱区域负担、恢复网络学习率、损伤侧形式、普通输入）已按登记顺序在跑，结果会写进第 4 节。**在对照出来之前，不能说收益来自核的结构。**

## 3. 单 seed 实验：剂量—易损性核（seed 0，事件五折，900 步）

- 损伤侧在五折里权重全为 0，没有启动；起作用的只有恢复侧。
- 恢复侧学到了方向：热带严重县-事件峰值处的恢复率从 0.262 降到 0.087（DKV）和 0.057（DK），观测约 0.05。DK 在热带 S 上 +4.7%。

- 失败的原因：它对所有规模、所有天气类型都放慢恢复（约一半），小停电和大风、强降雨事件因此变差。DKV 分天气类型的全体误差：热带 +2.9%，对流 +0.8%，冬季 −0.1%，大风 −7.2%，强降雨 −8.5%。
- DKVp（打乱易损性的 null）和 DKVr（只开恢复侧）没有运行：DKV 不是候选，易损性相对无易损性的基线没有增量（点估计为负）；DKV 的损伤侧权重为 0，本来就等同于只开恢复侧。

## 4. 单 seed 初筛：恢复核（起报点后移 48 小时）

设计与判定规则在运行前提交：[RESTORATION_KERNEL_DESIGN](RESTORATION_KERNEL_DESIGN_20261002_ZH.md)。

- 模型：恢复流量 r·p 改为 r·p / ((1 + κ_L·r·p)(1 + Σ κ_k·b_k))。第一项是自身规模饱和，第二项是三个距离环（0–50、50–150、150–300 km）邻县停电比例上的径向核。4 个参数，初值为 0，与宿主配对。
- 基线：宿主在同一后移面板上重新训练。

## 5. 建议（需要 PI 决定）

1. **主线从"风暴前起报 + 地理描述量"转到"恢复侧的时空核 + 滚动起报"。** 理由：这是唯一过关的空间信号；它正好回答"时间核为什么不和空间核联动"——联动发生在恢复侧，经由库存递推；IDEAS 里的 I15、I16 本来就指向恢复侧。
   - 具体提案见 [ROLLING_ORIGIN_DESIGN_PROPOSAL](ROLLING_ORIGIN_DESIGN_PROPOSAL_20261002_ZH.md)。
   - 模型的下一步：让区域负担随邻县的预测存量演化（现在固定在起报时的值，最大的热带系统里恢复得偏慢）。
2. **地理以空间邻近进入核**（距离上的径向核）。地形、冠层、土壤这类描述量建议停止投入。
3. **数据设计需要改动**：每个事件多个起报点。要定的有：取哪些起报点、如何加权、是否保留风暴前起报、评估按阶段还是合并。这是登记过的数据设计之外的改动，我没有擅自采用，只用后移 48 小时做了初筛。
4. **论文里可以主张什么**：按事件留出的定量结果、恢复侧空间核这个模型形式、滚动起报评估。不能说首次发现"大事件恢复慢"，也不能把机制写成抢修队饱和。
